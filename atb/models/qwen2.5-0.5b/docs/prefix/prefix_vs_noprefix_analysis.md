## 备注

- 表中 `#` 列对应每层算子的调用顺序（1-2 为图首，3-16 为每层循环，17-21 为图尾）
- K/V proj 和 Gate/Up proj 因 input/output shape 完全一致，数据库中无法区分，统计数据相同
- prefix 新增 2 个 GatherV2/层（步骤3 expand + 步骤9 compress），每请求各 24 次
- prefix 下 O/Gate/Up/Down/SiLU/AddRmsNorm 的计算量从 1500→1320 token（150场景，-12%）或 2180→1955 token（218场景，-10.3%），是 FFN 侧耗时下降的原因
- Q/K/V proj 和 FIA 仍在全量 token 上计算（需为所有 token 含 prefix 计算 KV cache），无计算量节省
